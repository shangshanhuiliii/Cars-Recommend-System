# 未实现功能与后续计划

本文档只列出当前未实现功能和后续可做的工程计划。这里的功能不属于当前系统行为，不能在接口、页面或说明中描述为已支持能力。

## 未实现功能

### 动态角色权限配置后台

当前系统已经实现基础登录、JWT 鉴权、USER / ADMIN 角色权限、菜单权限和接口权限。本阶段不提供动态角色、动态权限、动态菜单配置后台，也不提供角色管理 CRUD。

### 账号安全增强

当前系统已经实现登录 / 注册浮窗入口、普通用户注册、普通用户登录、管理员登录、管理员用户管理和启用 / 禁用。

当前注册已预留邮箱字段，但不发送验证码，也不提供密码重置。

后续增强项包括：

- 邮箱验证码注册。
- 邮箱找回密码。
- SMTP 发送配置和邮件模板。
- 验证码频率限制、有效期和错误次数控制。
- 短信验证、第三方登录、登录失败锁定、tokenVersion 和 token blacklist。

### Swagger/OpenAPI 文档

当前接口文档维护在 `docs/API.md`。自动生成的 Swagger/OpenAPI 页面尚未实现。

### Excel 批量导入

当前车型数据通过 SQL 种子数据和管理端页面维护。Excel 批量导入、模板校验和导入错误报告尚未实现。

### Redis 缓存

当前系统不依赖 Redis。推荐计算、历史读取、统计查询和本阶段登录注册流程均直接使用数据库与应用层逻辑。

后续只有在邮箱验证码、限流、token blacklist、多实例临时状态或明确缓存收益出现时，再评估 Redis 或其他临时状态存储方案；本阶段不引入 Redis。

### 外部商业车型数据源自动同步
当前系统已经提供管理端 JSON 车型数据源导入能力，可重复导入和更新 `car_model`、`car_param`，并返回导入摘要与问题列表。尚未实现需要商业授权、接口密钥或登录态的外部车型数据 API 自动同步，也不包含爬虫绕过反爬能力。

### 推荐反馈学习机制

当前反馈只进入统计，不做在线学习，不自动修改用户权重、车型评分或推荐排序。

可继续研究的方向：

- 基于反馈统计优化默认场景权重。
- 管理端展示反馈趋势。
- 在用户明确确认后生成新的偏好建议。

这些方向需要先更新推荐算法文档、数据库设计和测试。

### 高级 BI 图表

当前管理端已经提供运营概览，使用卡片和轻量条形图展示用户、车型、推荐、收藏和反馈指标。高级 BI 图表、复杂趋势分析、实时大屏和外部报表系统尚未实现。

### 更复杂的自然语言理解

当前后端自然语言解析接口使用规则词典和正则表达式，产品前端暂不展示该入口，主推荐流程使用结构化表单。更复杂的语义理解、多轮澄清或外部模型接入尚未实现。

### 自动化部署

当前文档覆盖本地运行。容器化部署、CI/CD、环境变量注入、备份恢复和线上监控尚未实现。

### 更细粒度车型配置

当前舒适分由空间、智能和口碑组合估算。座椅材质、悬架类型、隔音、空调分区等更细粒度配置字段尚未实现。

### 数据迁移管理

当前本地库通过 `schema.sql` 和 `seed-data.sql` 初始化。版本化迁移工具、线上迁移流程和回滚策略尚未实现。

## 后续计划建议

优先级应围绕当前可运行工程的稳定性和可维护性排序：

1. 补齐真实使用中的缺陷修复。
2. 增强车型数据质量，并评估真实云对象存储、CDN 和图片迁移策略。
3. 完善 Swagger/OpenAPI 或等价接口自动文档。
4. 评估是否需要账号安全增强和动态角色权限配置后台。
5. 加入数据迁移管理。
6. 评估 Excel 批量导入。
7. 在验证码、限流、token blacklist、多实例临时状态或明确性能收益出现时，再评估 Redis。
8. 研究反馈统计对权重建议的辅助作用。

任何会改变推荐排序、数据库结构或接口字段的计划，都必须先更新：

- `docs/API.md`
- `docs/DATABASE.md`
- `docs/RECOMMENDATION.md`
- `docs/FRONTEND.md`

并补充后端测试和前端验证。
