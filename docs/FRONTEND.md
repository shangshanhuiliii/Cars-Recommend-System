# 前端文档

本文档描述当前前端页面结构、交互规则和展示规范。前端实现必须服务于推荐主链路，重点展示“为什么推荐”和“哪里不足”，不能退化成普通车型列表。

## 体验目标

前端需要完成：

1. 让用户顺畅提交购车需求。
2. 清楚展示推荐结果、综合推荐分、推荐理由、不足提醒和维度评分。
3. 让推荐历史、管理端和算法可视化页面能够回查推荐依据。

推荐结果页是用户端最重要页面。它必须展示：

- 综合推荐分。
- 推荐标签。
- 推荐理由。
- 不足提醒。
- 维度评分。
- 查看详情入口。

## 视觉方向

视觉方向为 Apple-inspired 汽车决策产品体验。页面应克制、精致、高留白，像真实可用的购车决策产品，而不是汽车商城促销页、后台表格或泛 AI 模板。

关键词：

```text
克制
精致
高留白
强排版
柔和玻璃层次
真实产品感
可解释
```

避免：

- 紫色 AI 模板风、廉价大渐变和无意义装饰。
- 过多促销、价格刺激和营销按钮。
- 只有表格和表单、没有推荐解释的信息堆叠。
- 用户端展示 TOPSIS、Pareto、熵权等复杂算法术语。
- 与理解推荐结果无关的复杂动效。

## 全局布局

顶部导航按当前登录身份展示，左侧统一使用品牌 Logo 组件：

```text
未登录：品牌 Logo / 首页 / 右上角登录 / 注册按钮
USER：品牌 Logo / 首页 / 购车推荐 / 推荐历史 / 我的收藏 / 车型对比 / 账户按钮
ADMIN：品牌 Logo / 车型管理 / 用户管理 / 收藏车型 / 反馈记录 / 推荐记录 / 运营概览 / 系统健康检查 / 算法可视化 / 账户按钮
```

品牌图标从固定公开路径 `/brand/logo-icon.svg` 加载，品牌名称和副标题由前端统一配置维护。图标替换时只需更新 `frontend/public/brand/logo-icon.svg`，组件在图片加载失败时显示简洁文字 fallback，不出现破图。普通用户和未登录状态点击品牌进入 `/`，管理员点击品牌进入 `/admin/cars`。

主体区域建议最大宽度 `1240px`，左右留白 `24px`。

菜单来自登录响应或 `/api/auth/me` 返回的 `menus`，也可以用 `principalType` 做兜底展示。菜单隐藏不是安全边界，后端接口权限才是安全边界。

产品前端统一使用首页登录 / 注册弹窗。未登录右上角按钮打开弹窗；登录后右上角显示带边框和玻璃质感的账户按钮，点击后下拉展示昵称、角色和退出，不在顶栏直接裸露退出按钮。管理员展示名称固定为“管理员”。

登录 / 注册弹窗规则：

- 登录和注册在同一个弹窗内切换，不跳离首页。
- 登录模式底部保留“没有账号？立即注册”和“忘记密码”；点击“立即注册”切换到注册模式，点击“忘记密码”只展示占位提示。
- 忘记密码本阶段只提示“邮箱找回密码功能将在后续开放。当前请联系管理员协助处理。”，不发送邮件、不重置密码。
- 登录和注册提交前必须勾选“我已阅读并同意《用户协议》和《隐私协议》”；未勾选时阻止提交，并让协议区域执行轻微 shake 警示。
- 《用户协议》和《隐私协议》本阶段可以在弹窗内展示简洁占位说明，不新增强制独立路由。
- 注册普通用户时需要填写邮箱并保存到 `app_user.email`，作为后续找回密码能力基础；本阶段不触发邮箱验证码发送。

普通操作成功或失败不使用顶部 toast。收藏、取消收藏、加入对比、提交反馈等操作使用按钮状态、卡片内提示、表单区域提示或页面内状态条表达结果。

## 路由表

| 路由 | 页面 | 说明 |
| --- | --- | --- |
| `/` | 首页 | 面向普通用户的产品首页，顶部只展示数据库随机车辆图片轮播和极简车辆信息角标；轮播下方只保留核心购车推荐入口；特色区用可点击卡片进入 `/features`。 |
| `/login` | 兼容登录路由 | 不再展示独立页面，重定向到 `/?auth=login`，并透传合法 `redirect`。 |
| `/admin/login` | 兼容管理员登录路由 | 不再展示独立页面，重定向到 `/?auth=login&redirect=/admin/cars` 或透传合法 admin redirect。 |
| `/register` | 兼容注册入口 | 产品前端不再作为独立入口使用；注册由首页弹窗完成，只能创建普通 USER 账号。 |
| `/unauthorized` | 无权限页 | 登录身份与路由权限不匹配时展示。 |
| `/recommend` | 购车需求页 | USER 路由；产品化结构化需求表单，不展示自然语言解析入口。 |
| `/recommend/result/:recordId` | 推荐结果页 | USER 路由；读取推荐详情，车名可点击进入 `/car/{id}?recordId={recordId}`，按后端 `rankNo` 展示。 |
| `/car/:id` | 车型详情页 | 独立车型详情页，横屏大图展示基础信息、参数和特征评分。 |
| `/features` | 特色介绍页 | 公开页面；集中介绍结构化需求、推荐理由、不足提醒、收藏对比和历史回看，不展示复杂算法术语。 |
| `/history` | 推荐历史页 | USER 路由；展示当前用户推荐历史列表和详情入口。 |
| `/compare` | 车型对比页 | USER 路由；加载当前用户后端持久化对比列表，支持 1-3 款车型横向对比。 |
| `/favorites` | 我的收藏页 | USER 路由；展示当前用户收藏车型。 |
| `/algorithm-demo` | 算法可视化页面 | ADMIN 路由；管理端导航中的只读工具页，展示推荐快照中的算法过程。 |
| `/admin/cars` | 管理端车型管理 | ADMIN 路由；车型、参数、评分维护。 |
| `/admin/users` | 管理端用户管理 | ADMIN 路由；查看普通用户状态、统计数字、最近需求和推荐历史入口，点击用户行显示右侧详情，支持启用 / 禁用。 |
| `/admin/favorites` | 管理端收藏车型 | ADMIN 路由；只读展示车型收藏排行和收藏用户。 |
| `/admin/feedbacks` | 管理端反馈记录 | ADMIN 路由；只读展示用户反馈记录和筛选条件。 |
| `/admin/recommend-records` | 管理端推荐记录 | ADMIN 路由；追溯需求、权重、分数和解释。 |
| `/admin/dashboard` | 管理端运营概览 | ADMIN 路由；展示用户、车型、推荐、收藏和反馈运营统计。 |
| `/admin/health` | 管理端系统健康检查 | ADMIN 路由；调用 `GET /api/health` 查看后端服务和数据库状态。 |

路由守卫规则：

- 未登录访问 USER / ADMIN 路由时跳转 `/?auth=login&redirect=<to.fullPath>`。
- `/login` 和 `/admin/login` 只作为兼容路由，访问后重定向到首页并打开登录弹窗。
- 登录成功后，ADMIN 在 redirect 是合法 admin 路由时进入 redirect，否则进入 `/admin/cars`；USER 在 redirect 是合法 USER 路由或公开路由时进入 redirect，否则进入 `/`。
- 注册成功后自动保存 USER 登录态；有合法 USER 或公开 redirect 时进入 redirect，否则进入首页 `/`。
- USER 访问 ADMIN 路由、ADMIN 访问 USER 路由时进入 `/unauthorized`。
- ADMIN 访问 `/` 重定向 `/admin/cars`；ADMIN 访问 `/login`、`/admin/login` 或 `/register` 也重定向 `/admin/cars`。
- Axios 请求拦截器自动附加 `Authorization: Bearer <token>`。
- Axios 响应拦截器遇到 `401` 清除本地登录态，并跳转 `/?auth=login&redirect=<currentPath>`。

## 首页

首页是面向普通用户的产品首页，不承担运行检查、管理端排查或算法说明职责。

首页结构：

- 顶部车辆轮播只展示数据库随机返回的车型图片和极简车辆信息角标，数据来自公开接口 `GET /api/car/home-carousel?limit=6`。
- 轮播高度约占视口 1/3，建议使用 `clamp(240px, 33vh, 340px)`；保持车辆图片正常展示比例，不做细长横幅。
- 轮播主体可以适当收窄居中，两侧留白可使用 Apple-inspired 的柔和 radial-gradient 光斑、极淡线条或玻璃层次装饰，但不堆文案、不做 AI 风视觉。
- 轮播整张 slide 可点击进入 `/car/{id}`；轮播不展示解释性文案，不放“开始推荐”“查看历史”“我的收藏”“车型对比”等功能 CTA。
- 轮播优先使用车型 `imageUrl`，通过 `carImageSrc(imageUrl)` 兜底，本地开发库没有审核通过图片时仍保持页面可用。
- 轮播下方只保留“开始购车推荐”核心入口，文案简短，CTA 跳转 `/recommend`。
- 首页删除推荐历史、我的收藏、车型对比等辅助入口卡片；这些入口由导航栏提供。
- 特色介绍集中为克制的可点击功能卡片，例如结构化购车需求、推荐理由、不足提醒、车型收藏与对比、历史回看；点击进入 `/features` 的对应 section。

首页不得调用 `GET /api/health`，不得展示健康检查状态；不得把算法可视化作为首页主入口；不得展示 TOPSIS、Pareto、熵权等复杂算法术语。

## 购车需求页

页面目标：帮助用户用克制、清晰的结构化表单提交购车需求。

必须字段：

- 预算下限 `budgetMin`。
- 预算上限 `budgetMax`，为空表示不限上限。
- 品牌 `brands`，多选，空数组表示全部品牌。
- 车型类型 `bodyTypes`，多选，空数组表示全部级别。
- 动力类型 `energyTypes`，多选，空数组表示全部动力。
- 座位数选项 `seatOptions`，多选，空数组表示全部座位。
- 使用场景 `scenes`，多选。
- 显式偏好权重 `factorWeights`，0-10 滑块。

展示规则：

- 预算前端用“万元”按钮组展示，包含 `10万以下`、`10-15万`、`15-20万`、`20-25万` 和自定义范围；提交给后端时转换为元。
- 自定义预算使用双点范围滑块，`105` 表示“不限”，提交时转换为 `budgetMax = null`。
- 车型类型支持 `轿车 / SUV / MPV / 跑车 / 卡车` 组合选择。
- 动力类型支持 `燃油 / 纯电 / 插混 / 增程 / 新能源` 组合选择。
- `新能源` 由后端展开匹配，不写入车型表。
- 座位数支持 `2座 / 4座 / 5座 / 6座 / 7座 / 7座以上`，其中 `7_PLUS` 表示 7 座及以上。
- 使用场景使用卡片多选，不只用下拉框。
- 偏好权重维度为价格、空间、安全、能耗、智能、舒适、动力、口碑、热度。
- 全部滑块默认 0，后端按使用场景生成默认权重。
- 只要有滑块大于 0，后端以归一化后的滑块值作为主观权重。
- 不展示推荐数量输入。

自然语言解析：

- 后端 `POST /api/user/demand/parse-text` 接口保留。
- 当前产品前端不展示该入口，也不在主推荐流程中调用。
- 用户通过结构化表单提交需求。

## 推荐结果页

页面必须回答：

```text
推荐了什么？
为什么推荐？
哪里不足？
是否满足严格推荐条件？
如果不满足严格推荐条件，系统如何补充推荐？
```

信息结构：

```text
用户画像摘要
-> 推荐结果列表
-> 维度解释和权重说明
-> 重新填写需求 / 反馈 / 对比入口
```

推荐分组：

- `为您推荐`：`matchLevel = STRICT`，表示满足预算区间、车型类型、动力类型、最低座位数和排除条件等严格条件。
- `推荐`：非 `STRICT` 推荐项，表示系统在保持不可放宽约束的基础上，对预算、车型或动力做有限放宽的补充推荐。

排序规则：

- 每组内部必须按后端 `rankNo` 升序展示。
- 不按 `totalScore`、`reputationScore`、`popularityScore` 或其他字段二次排序。
- `rankNo` 是展示排序的唯一权威。

推荐卡片必须展示：

- 排名。
- 车型图片。
- 品牌和车型名称。
- 指导价。
- 综合推荐分 `totalScore`。
- 推荐标签 `tags`。
- 推荐理由 `reasonText`。
- 不足提醒 `weaknessText`。
- 维度评分。
- 车名详情链接。
- 加入对比。
- 收藏。

推荐卡片采用横向车辆图片 + 右侧标题信息 + 下方推荐理由 / 不足提醒 / 九维分的结构，图片比例保持横屏，不使用窄竖条。用户端不展示 TOPSIS、Pareto、熵权等算法术语。

匹配状态与推荐标签必须视觉分离：

- 用户端卡片不展示 `RELAX_*` 或 `SIMILAR_RECOMMEND` 作为主要标签。
- `tags` 只展示车型优势，例如“空间优秀”“安全配置高”“价格匹配度高”。
- 管理端和历史详情可展示 `matchLevel`、`recommendStatus`、`fallbackMessage`。

加入对比交互：

- 点击“加入对比”只更新当前对比列表和按钮状态。
- “加入对比”调用 `POST /api/user/compare/{carId}`，不再把车型 ID 写入浏览器固定 `localStorage` key。
- 用户主动点击“查看对比（N/3）”后进入 `/compare`。
- 从对比页返回时应回到原推荐记录，并尽量恢复原位置。

反馈交互：

- 推荐结果页底部展示反馈卡片。
- 反馈提交到 `recommend_feedback`。
- 提交成功或失败在反馈卡片内展示。
- 反馈不改变推荐排序。

## 推荐生成状态

生成中状态不应只是普通 loading。建议展示：

```text
正在解析购车需求
正在计算车型匹配度
正在生成推荐理由
```

错误状态应说明问题和下一步操作，例如：

```text
推荐生成失败，请检查需求信息后重试。
```

空状态应说明原因和下一步：

```text
暂无推荐记录，您可以先填写购车需求生成推荐。
```

## 车型详情页

页面目标：展示车型完整信息，帮助用户查看参数、配置和特征评分。

必须展示：

- 品牌。
- 车系。
- 车型名称。
- 指导价。
- 车型类型。
- 动力类型。
- 座位数。
- 上市年份。
- 车身尺寸。
- 轴距。
- 油耗或续航。
- 安全配置。
- 智能配置。
- 多维评分。

评分展示使用清晰的条形图或指标列表。页面不展示 `GET /api/{...}` 等接口说明，也不使用测试或演示化文案；从推荐结果进入时保留“返回推荐结果”按钮。

## 推荐历史

历史推荐必须展示：

- 推荐时间。
- 用户画像。
- 推荐状态。
- 补充推荐提示追溯字段。
- 推荐标签快照。
- 查看推荐明细入口。

推荐明细展示推荐发生时保存的 `tags`、分数、理由、不足和匹配状态。不要根据当前评分规则重新生成历史标签。

## 车型对比

页面目标：帮助用户查看和横向比较 1-3 款车型。

规则：

- 数据来自当前登录用户的 `GET /api/user/compare`。
- `/api/car/compare?carIds=1,2,3` 只作为公开静态车型对比查询保留，不保存用户选择。
- 推荐结果页、车型详情页和收藏页加入对比都调用 `/api/user/compare/{carId}`。
- 对比列表跟随当前 USER 后端持久化保存，用户换设备登录后仍能读取自己的对比列表。
- 管理员不使用用户级车型对比。
- 页面只读取车型基础信息、参数和车型静态评分。
- 不调用推荐生成接口。
- 不影响 `pareto-topsis-v1` 推荐排序。
- 雷达图使用八维车型静态评分：空间、安全、能耗、智能、舒适、动力、口碑、热度。
- 价格只展示在基础信息表，不放入雷达图。
- 评分缺失时显示“暂无评分，请在管理端重算评分”。

## 收藏

收藏页展示：

- 车型图片。
- 车型名称。
- 指导价。
- 车型类型。
- 动力类型。
- 查看详情。
- 取消收藏。

规则：

- 推荐结果卡片和车型详情页提供收藏入口。
- 收藏、取消收藏和状态查询使用当前用户。
- 收藏状态加载失败时不影响推荐主流程。
- 收藏成功或取消收藏后只通过按钮文字和页面内状态体现。
- 收藏只记录用户关注车型，不参与推荐排序和权重计算。

## 用户反馈

反馈表单字段：

- 满意度评分，1-5。
- 原因标签。
- 文字反馈。
- 提交成功状态。

建议原因标签：

- 价格偏高。
- 空间太小。
- 品牌不喜欢。
- 动力类型不合适。
- 配置不够。
- 油耗或续航不满意。
- 推荐结果不够准确。
- 推荐有帮助。
- 解释清楚。

反馈进入管理端统计，但不用于在线学习，不自动更新权重、车型评分或推荐排序。

## 管理端

管理端服务于推荐数据基础、推荐追溯和统计，不做复杂运营后台。

当前页面：

```text
车型管理
用户管理
收藏车型
反馈记录
推荐记录
运营概览
系统健康检查
算法可视化
```

管理员界面不展示首页入口，品牌 Logo 指向 `/admin/cars`，右上角名称固定显示“管理员”。管理员登录后默认进入 `/admin/cars`，不能进入普通首页。

用户管理页规则：

- 列表不提供“详情”按钮，点击用户行在右侧显示详情。
- 操作列只保留启用 / 禁用。
- 推荐状态展示为中文：`SUCCESS` 为“完全匹配”，`FALLBACK` 为“含补充推荐”，`EMPTY` 为“暂无结果”。
- 详情页保留基础信息、统计数字、最近需求和推荐历史入口。
- 详情页不展示收藏车型预览和反馈记录预览。
- 跳转入口指向 `/admin/recommend-records?userId={id}`、`/admin/favorites?userId={id}`、`/admin/feedbacks?userId={id}`。
- 用户管理不触发推荐生成，不允许管理员代用户收藏、反馈或生成推荐。

车型管理页支持：

- 新增车型。
- 编辑车型。
- 删除车型。
- 车型表格展示当前生效图片缩略图，空图片继续使用兜底图。
- 在车型基础信息弹窗中保留手动 `imageUrl` 维护能力。
- 在已保存车型上下文中上传 JPG / PNG 图片、查看预览和资源状态。
- 查看该车型图片资源列表，并对 `PENDING` 资源执行通过或拒绝审核。
- 图片审核通过后由后端更新车型当前图片；拒绝或删除资源不改变推荐排序。
- 维护参数。
- 查看评分。
- 重新计算评分。

图片资源状态展示：

- `PENDING` 展示为待审核，允许通过或填写拒绝原因后拒绝。
- `APPROVED` 展示为已通过，表示可成为车型当前生效图片。
- `REJECTED` 展示为已拒绝，并展示拒绝原因。

用户端推荐结果页、车型详情页、收藏页和对比页仍只读取接口返回的 `imageUrl`，通过 `carImageSrc(imageUrl)` 展示当前生效图片或兜底图。前端不得根据图片是否存在、审核状态或资源数量调整推荐结果顺序。

推荐记录页必须展示：

- 推荐时间。
- 用户需求。
- 用户画像。
- 权重快照。
- 推荐状态。
- 补充推荐提示追溯字段。
- 推荐明细。
- 排名、车型、总分、各维度分、标签快照、匹配状态、推荐理由和不足提醒。

推荐记录为空时展示“暂无推荐记录”，入口按钮指向 `/admin/users` 的用户管理页，便于管理员按用户查看历史；不得跳转到 USER 专属的 `/recommend`。

收藏车型页规则：

- 路由为 `/admin/favorites`。
- 默认展示收藏车型排行，按收藏数从大到小排序。
- 点击车型后在右侧查看收藏该车型的用户。
- 从 `/admin/favorites?userId=123` 进入时筛选该用户收藏过的车型，但车型收藏数仍展示全站总量。
- 页面只读，不提供取消收藏、删除或代用户操作。

反馈记录页规则：

- 路由为 `/admin/feedbacks`。
- 列表展示每条反馈的用户、推荐记录 ID、满意度、原因标签、评论和时间。
- 支持关键字、用户 ID 和满意度评分筛选。
- 推荐记录 ID 可跳转 `/admin/recommend-records?recordId=xxx`。
- 页面只读，不提供删除或修改；反馈不进入推荐学习。

运营概览展示：

- 用户总数、ACTIVE 用户数、DISABLED 用户数。
- 车型总数、推荐记录数、今日推荐记录数、最近 7 天推荐记录数。
- 收藏总数、反馈总数和平均满意度。
- 预算区间分布。
- 使用场景分布。
- 显式偏好权重分布。
- 热门推荐车型。
- 推荐状态分布，用户可见文案中文化为完全匹配、含补充推荐、暂无结果。
- 车型类型偏好分布。
- 动力类型偏好分布。
- 收藏最多车型。
- 满意度分布。
- 原因标签分布。

统计图表消费 `{ name, value }` 数组。没有数据时展示空状态，不展示无意义随机数据。

系统健康检查页：

- 路由为 `/admin/health`。
- 页面名称为“系统健康检查”。
- 调用 `GET /api/health`。
- 展示后端服务状态、数据库状态和检查时间。
- 提供“重新检查”按钮。
- 原始返回信息通过折叠区域展示。

## 算法可视化页面

`/algorithm-demo` 是管理端导航中的独立只读页面，用于说明推荐算法过程，不进入普通推荐主流程，不影响推荐结果生成。

页面只调用：

```text
GET /api/admin/recommend-records
GET /api/admin/recommend-records/{recordId}/algorithm-visualization
```

页面不得调用 `POST /api/recommend/generate`，不得在前端重新计算推荐排序，也不得覆盖后端 `rankNo`。

页面至少展示：

- 推荐记录选择区。
- 算法流程总览。
- 用户需求与约束。
- 车型特征评分说明。
- 主观权重、客观权重、组合权重和 `alpha`。
- 候选层级统计。
- 九维评分矩阵。
- Pareto-TOPSIS 排序信息。
- 推荐解释。
- 快照追溯说明。

该页面可以展示 TOPSIS、Pareto、熵权等术语。普通用户推荐结果页不展示这些复杂术语。

## 响应式规则

需要保证以下宽度可用：

- 1440px 桌面屏。
- 1366px 笔记本屏。
- 768px 平板宽度。

移动端做基础适配即可。文本、按钮、评分条和卡片内容不能重叠。
首页在移动端需要保证顶部导航可用、轮播内容不溢出、入口卡片单列展示。

## 验收清单

- 用户能从首页进入购车需求页。
- 用户填写需求后能看到推荐结果。
- 推荐结果页展示 `tags`、`reasonText`、`weaknessText`、维度分数和分组语义。
- 推荐结果页按 `rankNo` 展示，不二次排序。
- 用户能进入车型详情页查看参数和评分来源。
- 历史页展示推荐发生时的快照信息。
- 管理端推荐记录页能复现历史推荐依据。
- `/algorithm-demo` 只读展示权重、候选、九维矩阵、Pareto、TOPSIS、解释和快照边界。
- 普通操作反馈使用页面内状态。
- 推荐算法不写在前端。
