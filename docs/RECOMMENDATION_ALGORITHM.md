# 车型特征评分规则说明

本文档只维护车型静态特征评分规则。当前主推荐算法、TOPSIS 公式、Pareto 辅助排序、解释生成和快照规则见 `RECOMMENDATION_ALGORITHM_UPGRADE.md` 与 `RECOMMENDATION_IMPLEMENTATION_LOGIC.md`。

车型特征评分的职责是把 `car_model` 和 `car_param` 中的车型基础数据转成 0-100 的静态评分向量，保存到 `car_feature_score`，供推荐、车型详情、车型对比和管理端追溯使用。

## 1. 评分输入

评分来源：

| 数据来源 | 用途 |
| --- | --- |
| `car_model` | 品牌、车型名称、指导价、车型类型、动力类型、座位数、销量、口碑、审核状态 |
| `car_param` | 车身尺寸、轴距、油耗、续航、动力、安全配置、智能配置 |
| `car_feature_score` | 保存计算后的八维静态评分 |

基础规则：

- 所有评分范围为 0-100，分数越高表示该维度表现越好。
- 车型必须审核通过、未软删除且存在评分后，才进入推荐候选。
- `priceScore` 不属于静态车型评分，不写入 `car_feature_score`；价格匹配分只在推荐阶段根据用户预算动态计算。
- `car_model.energy_type` 只保存具体动力类型，例如 `燃油 / 纯电 / 插混 / 增程`；用户需求侧的 `新能源` 由后端展开为 `纯电 / 插混 / 增程`。

## 2. 评分维度

`car_feature_score` 当前维护八个静态维度：

| 评分字段 | 含义 | 主要来源 |
| --- | --- | --- |
| `space_score` | 空间表现 | 轴距、车长、座位数、车型类型 |
| `safety_score` | 安全配置水平 | 气囊、ABS、ESP、主动刹车、车道保持、自适应巡航、并线辅助 |
| `energy_score` | 能耗或续航表现 | 燃油车油耗、纯电续航、插混和增程综合续航 |
| `intelligence_score` | 智能配置水平 | 语音、OTA、中控屏、倒车影像、360 影像、辅助驾驶、自动泊车 |
| `comfort_score` | 舒适性估算 | 空间、智能、口碑组合估算 |
| `power_score` | 动力表现 | 百公里加速 |
| `reputation_score` | 口碑表现 | 用户评分换算 |
| `popularity_score` | 热度表现 | 销量按全局最大销量归一化 |

## 3. 空间分

空间分综合轴距、车长、座位数和车型类型。

建议解释口径：

- 轴距越长，车内纵向空间基础越好。
- 车长越长，乘坐和装载空间基础越好。
- 座位数越多，对家庭或多人出行更友好。
- SUV、MPV、轿车的空间基础不同，按车型类型给出合理修正。

评分必须限制在 0-100。缺少关键尺寸时可以使用保守默认分，但不能把缺失数据解释为高分。

## 4. 安全分

安全分由被动安全和主动安全配置共同决定。

主要加分项：

- 安全气囊数量。
- ABS。
- ESP。
- 主动刹车。
- 车道保持。
- 自适应巡航。
- 并线辅助。

解释口径：安全分表示配置层面的安全辅助能力，不等同于权威碰撞测试成绩。

## 5. 能耗分

能耗分根据动力类型采用不同来源：

- 燃油车：油耗越低，能耗分越高。
- 纯电车：纯电续航越高，能耗分越高；有电耗数据时可结合电耗修正。
- 插混和增程：综合续航越高、亏电油耗或电耗越低，能耗分越高。

能耗分用于推荐中的 `energy` 维度。它既反映使用成本，也反映续航便利性。

## 6. 智能分

智能分衡量车机和辅助驾驶配置。

主要加分项：

- OTA。
- 语音控制。
- 中控屏尺寸。
- 倒车影像。
- 360 全景影像。
- 辅助驾驶等级。
- 自动泊车。

解释口径：智能分表示配置丰富程度和日常便利性，不代表自动驾驶能力。

## 7. 舒适分

当前版本不额外维护座椅材质、悬架类型、隔音、空调分区等细粒度舒适配置，因此舒适分采用组合估算：

```text
comfortScore = spaceScore * 0.5 + intelligenceScore * 0.2 + reputationScore * 0.3
```

后续如增加舒适性参数，必须先更新 `DATABASE_DESIGN.md`、本文件和相关测试，再调整评分实现。

## 8. 动力分

动力分主要根据百公里加速计算。

解释口径：

- 加速时间越短，动力表现越强。
- 动力分只表示性能倾向，不代表用车经济性。
- 家用场景不一定需要最高动力分，应由推荐算法结合用户权重综合判断。

## 9. 口碑分

口碑分由 `car_model.user_rating` 换算得到。

建议口径：

```text
reputationScore = userRating / 5 * 100
```

如果评分缺失，应使用中性或保守默认值，并在管理端或数据质量检查中提示补齐。

## 10. 热度分

热度分由销量或测试热度归一化得到：

```text
popularityScore = salesVolume / maxSalesVolume * 100
```

由于热度分依赖全局最大销量，修改 `sales_volume` 后建议执行全部车型评分重算，保证归一化结果一致。

## 11. 重算规则

评分重算入口：

```text
POST /api/admin/cars/{id}/score/recalculate
POST /api/admin/cars/scores/recalculate
```

重算要求：

- 单车参数变化后，可执行单车评分重算。
- 销量变化、评分规则变化或初始化种子数据后，应执行全部车型评分重算。
- 初始化数据库后必须执行全部车型评分重算，否则推荐候选可能不足。
- 评分结果写入 `car_feature_score`，并更新 `score_version` 与 `calculated_time`。

## 12. 与推荐算法的边界

车型特征评分只负责生成静态评分向量，不负责推荐排序。

推荐阶段会在静态评分基础上继续处理：

- 用户需求硬约束。
- 动态 `priceScore`。
- 用户主观权重。
- 熵权法客观权重。
- 主客观组合权重。
- Pareto 辅助排序。
- TOPSIS 综合推荐分。
- 推荐理由、不足提醒和快照保存。

这些推荐阶段规则统一维护在 `RECOMMENDATION_ALGORITHM_UPGRADE.md` 和 `RECOMMENDATION_IMPLEMENTATION_LOGIC.md`。
